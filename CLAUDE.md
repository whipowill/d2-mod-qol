# Diablo II QOL tweaks (qol.dll) - project summary and standing rules

Project summary, standing rules, status and build commands (kept short: this file is loaded every session). The engineering knowledge (addresses, packet formats, dead ends) lives in **NOTES.md** - read the section a task touches, and put new findings there, not here. Addresses are RVAs unless a full `6fxxxxxx` virtual address is given.
Items marked **[confirmed]** were verified in the real game by the user; everything else was built from disassembly / packet logs and is only as good as the test stated next to it.

---------------------------------------------------------------------------------------------------------------------------------
## 1. What this is
A 32-bit Windows DLL (`qol.dll`, config `qol.ini`, log `qol.log`) for **single-player** Diablo II. Primary target: stock/modded **LoD 1.13d** (the user's game, loaded via PlugY's `DllToLoad`);
also works with Project Diablo 2 (PD2, under Wine, loaded via D2GL `load_dlls_late`) for the parts that are version-independent. Cross-compiled on Linux with zig. Single player / offline only,
so there is no anti-cheat concern.

### User preferences / standing rules (apply to all future work)
- **Never require numeric config values**: everything is learned or read from the game's own files. Settings default to **off** (the pickup and clicker are ON in the template).
- **Leave game files unmodified** (play with the original DLLs): all code changes happen in memory at runtime, found by byte signature, gated by PE timestamps.
- **Play nice with BaseMod** (devurandom's BaseMod.dll): never fight its `[MercMod]` replacements; detect and step aside.
- The ini and docs should **not mention PD2**.
- The user commits and pushes themselves. Don't commit unless asked.
- Master switch `[qol] enabled`; per-feature `enabled` switches; `[qol] logging=0|1`.
- Shipped names: `qol.dll`, `qol.ini`, `qol.log`. Source `src/qoltweaks.c`;
  `src/qoltweaks.ini` is the template build.sh copies to `build/qol.ini`.

## 2. Build, test, install
```
pip install --target .tools ziglang pefile capstone     # one-time; .tools/ is gitignored
./build.sh              # -> build/qol.dll (PE32 i386) + build/qol.ini
./build.sh mercdebug    # -> .out/mercdebug/qol.dll (diagnostic trace build, -DMERCDEBUG; never ship)
./test.sh               # native tests: rules (core), merc rules/class/slot/ids, signature finders; must print 0 FAIL
```
- Cross compile: `python3 -m ziglang cc -target x86-windows-gnu`. `python3 -I` ignores PYTHONPATH, so analysis scripts do `sys.path.insert(0, '.tools')`.
- Do NOT name a helper script `dis.py` (shadows the stdlib `dis` module and breaks capstone's import).
- `wine` here cannot be used to run the game (version mismatch with the already-running wineserver); test in the real game. Don't kill that wineserver.
- `.gitignore` tracks only `build/qol.dll` and `build/qol.ini`; `local.conf`, `reset.sh`, `.tools/`, `.out/` are ignored (`local.conf.example` is the template; `GAME_DIR`, `GAME_MPQS` live in local.conf).
- Source layout: `src/core.c/.h` (pure pickup logic, no Windows calls), `src/merc.c/.h` (pure merc rule logic), `src/sig.h` (pure byte-pattern finders), `src/tables.h` (belt code->slots prior,
  generated by `tools/gen_tables.py` from Armor/Belts/ItemTypes in the game's MPQs; handles PKWARE-implode sectors in stock Blizzard MPQs), `src/qoltweaks.c` (all Win32 glue, hooks, patches), `test/*.c`.
- Disassembly workflow: map a DLL with `pefile`'s `get_memory_mapped_image()` and use capstone x86-32; scan for `E8 rel32` call targets to find callers; dump data tables as dword runs.

### Where the game files are (paths live in the gitignored `local.conf`, not here)
- The LoD install being modded: a modded LoD 1.13d folder with loose `Data\` tables and launcher flags `-direct -txt` (holds `qol.dll`, `qol.ini`, `qol.log`, `BaseMod.ini`). Its `Backups/` folder holds `D2gfx.dll`,
  `Patch_D2.mpq` and a `README.txt` (hashes + explanation).
- A fresh, untouched stock LoD install is the master original to disassemble.
- The hex-edited DLLs the user made earlier (`D2Game_hexedits.dll`, `D2Game_snakeskeepequip.dll`) live in a separate folder next to the repo.
- Loading: PlugY `DllToLoad=qol.dll` (user must update `PlugY.ini`), or D2GL `d2gl.json` -> `other.load_dlls_late` (separator `,`, e.g. `"SGD2FreeRes.dll,qol.dll"`; the PD2 launcher may rewrite it).
- The DLL writes `qol.log` in the game dir (cwd).
